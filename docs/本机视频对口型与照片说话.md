# 本机视频对口型与照片说话

本功能支持官方 LatentSync 1.5（256×256 人脸区域）和 1.6（512×512 人脸区域），均保留 16 帧时序窗口。默认 20 步、引导强度 1.5，FP16、VAE 分帧和 CPU 人脸检测降低显存占用。主界面的 TTS 依赖和视频依赖分进程使用，生成视频前释放已加载的语音模型；训练或语音识别与视频推理互斥。

## 硬件自动选择

| NVIDIA 独立显存 | 自动策略 |
| --- | --- |
| 16 GB 及以上 | 已安装 1.6 时选择 1.6 高清低显存模式；空闲显存不足时停止并保留选择 |
| 8 GB～不足 16 GB（含 10 GB、12 GB） | 1.5 低显存模式 |
| 不足 8 GB、无 CUDA 或集成显卡 | 暂不启用生成，提示硬件要求 |

页面展示显卡型号、总显存、当前空闲显存和选择原因，也可手动选择版本。总容量阈值给驱动保留少量容差；共享显存和多块显卡容量不会累加。Windows WDDM 下 CUDA 可能高估空闲显存，程序按 UUID 对应同一显卡，取 CUDA 与 `nvidia-smi` 返回的较小值。

生成前释放本程序的语音模型并重新检测。1.6 空闲显存不足或子进程报告 CUDA 显存不足时，停止任务、释放子进程并保留模型选择，提示关闭其他占用显卡的程序后重试，不自动切换到 1.5。自动模式按总容量选择版本，当前空闲显存不再改变选择；1.6 未安装时仍可使用已安装的 1.5。开始推理至少需要 4 GiB 空闲显存；手动 1.6 至少 6 GiB，自动 1.6 保留 7 GiB 余量。这是保守调度规则，不代表已在所有显卡实测。

## 使用

1. 打开本机版 `JVOX Studio配音系统.exe`，进入「视频对口型」。
2. 选择已有视频或照片，再选择本地配音、刚生成的声音或配音作品。
3. 视频比配音短时，可循环原片或停在尾帧。点击生成，完成后播放、查看最近作品或另存 MP4。
4. 任务进行中可取消；重新打开页面或重载会恢复当前任务与已保存结果。服务重启后，未完成任务会明确提示失效，已有作品保留。

照片模式保持原照片姿态，驱动嘴部。优先使用单人、正面或轻微侧脸、脸部清晰无遮挡的素材。脸部生成分辨率按模型为 256 或 512，原始画面按方向最多保留到横屏 1920×1080、竖屏 1080×1920，不主动放大小素材；最终音轨来自原始配音。

支持 0.32～120 秒配音，长素材建议分段。当前实测为 1.28/1.36 秒短样片，未对 120 秒长片进行性能和内存压测。官方建议至少 8GB 显存；本轮实测为 16GB 的 RTX 4070 Ti SUPER，不把进程峰值当成其他显卡的容量保证。

## 本机模型与安装

普通用户通过页面自动补齐，无需另外安装Python、pip或C++编译工具。首次进入按硬件选模型：16GB及以上补齐1.6，8～不足16GB补齐1.5。组件默认保存在程序数据目录的`lipsync/`，只下载当前版本；主权重约5.07GB，另有约0.9GB引擎/依赖/辅助资源，建议磁盘至少保留10GB。主CUDA/PyTorch复用，视频依赖独立，不改动TTS环境。

补齐从魔搭固定资源下载，支持暂停、断点续传和失败重试；长度与SHA256校验通过才提交文件。验证CUDA、torchvision和人脸模型后写入就绪缓存，再次进入或重启复用记录，缺失或版本变化才修复。低于8GB或无可用NVIDIA CUDA显卡不启动大文件下载。总显存决定默认版本，1.6空闲不足仍停止，不改装1.5。

RTX50系由主运行时选择CUDA12.8，视频环境使用相匹配的torchvision。本机实测是CUDA12.6，CUDA12.8分支尚未在50系实机验证。


当前模型根目录是 `G:/app/VoxCPM-2.0.2/data/lipsync`。在高级参数中可以选择其他完整环境；错误目录会被拒绝，保留原配置。状态会同时检查 FFmpeg、ffprobe、共享依赖、对应模型配置/权重/版本清单，避免混用 1.5 和 1.6。兼容早期记录固定源码与模型版本的 1.6 清单。

以下为开发者手工备用入口，在 `Electron版本` 下运行：

```powershell
python scripts/setup_lipsync.py --root ../data/lipsync
# 同时安装两套权重，便于手动切换（每套主权重约 5.07 GB）
python scripts/setup_lipsync.py --root ../data/lipsync --model-version both
# 也可明确指定 --model-version 1.5 或 --model-version 1.6
```

使用 Windows Python 3.10～3.12，并确保 FFmpeg 和 ffprobe 在 PATH，或放入模型根目录 `tools/`。脚本建立专用 venv，安装固定版本依赖，再按硬件选择并下载固定版本源码与权重。追加版本只写对应 `runtime-版本.json`，不覆盖另一版本的运行清单与验证记录。`--reuse-installed-torch` 仅用于已有兼容 CUDA PyTorch 的本机开发环境；当前机器采用该模式，未修改主程序 TTS 环境。本轮没有重新下载安装另一套完整的冷环境 CUDA 依赖。

固定来源：

- 源码：`bytedance/LatentSync`，提交 `a229c3948406bc2cf6eaf4873e662e70c6a04746`，使用其中 `configs/unet/stage2.yaml` 的 256px 配置。
- 权重：`ByteDance/LatentSync-1.5`，版本 `32a20d29aead0498e3e885e90dbbe8027da1b61b`，保存到 `source/checkpoints/latentsync-1.5/`，严格匹配加载。
- 高清权重：`ByteDance/LatentSync-1.6`，版本 `c42c7e6c8e9c213626389fa7d9a3c444b8536353`，保存到 `source/checkpoints/latentsync_unet.pt`，配合 `stage2_512.yaml` 严格加载。“低显存优化”复用标准权重，不是另一套模型。
- VAE：`stabilityai/sd-vae-ft-mse`，版本 `31f26fdeee1355a5c34592e401dd41e45d25a493`。Whisper 和人脸检测文件复用已安装资源。

原 1.6 权重保留，原运行清单另存为 `runtime-1.6.json`。推理阶段明确使用本地路径并关闭 Hugging Face 在线下载。模型文件不纳入 Git 或程序包。
