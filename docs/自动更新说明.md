产品现正式更名为 **JVOX Studio配音系统**。旧安装目录、模型标识、更新协议、公钥、仓库ID和数据目录保持兼容；旧主程序文件可作为兼容入口继续使用，升级同时创建新名称启动入口并迁移归属明确的快捷方式及卸载名称。首次进入新版时第一屏直接展示更名庆祝页，无需等待本地服务，点击后进入工作台；后台资源准备不会覆盖庆祝页，选择“开启新声，开始创作”后不再重复提示；“稍后提醒”在下次启动继续展示。

当前正式版本为 `2.0.3 / 20261019103629`，启动发现新版直接打开独立更新器，选择后自动完成下载、校验、安装及重启；包含更新切换开关、音乐模型误报修复和使用前自动修复。默认更新源为 [魔搭专用仓库](https://modelscope.cn/models/jiangjiang419/voxcpm-studio-updates)，普通用户无需账号、Token 或代理。

历史发布：2026-10-19 发布 `2.0.2 / 20261018235215` 及[单文件老用户更新修复器 EXE](https://modelscope.cn/api/v1/models/jiangjiang419/voxcpm-studio-updates/repo?Revision=master&FilePath=repairers%2F2.0.2%2F20261018235215-0f71f753d9%2FVoxCPM-Update-Repairer.exe)。修复器自带最小更新环境，支持版本记录或更新文件损坏、同发布再次修复、旧事务恢复和旧启动入口修正；修复后常规更新使用独立Python，环境缺失或损坏自动补齐。修复器、更新包及最新入口均匿名回读核验。用户只需保存任务、双击EXE、确认原目录、点击「开始修复并升级」；自动关闭并强制结束该目录隐藏进程，详见[使用说明](./老用户更新修复器使用说明.md)。

修复器与原生独立更新器均复用安装器品牌、波形、暖白/深色主题、圆角卡片和按钮。常规更新仍从会话目录运行 `JVOX Updater.exe`，不加载待替换目录中的JS界面。工作台退出后，独立窗口继续安装、执行回滚或自动打开新版；保留发布序号、持久更新结果和失败日志。

已确认庆祝页面后的正常启动先进入工作区，不执行所选模型的全量校验或音乐环境自检；连接服务时可以先浏览界面，使用对应模型时才进行校验和加载。首次安装及用户显式完整准备仍展示资源检查、下载和安装进度。工作区及基础 API 就绪后自动检查更新，新流程直接打开原生独立更新器，提供“现在更新”和“下次启动更新”；选择前不下载，同次运行不重复自动提醒，网络失败不影响创作。旧客户端首次安装本次更新仍需使用其原有“查看更新/下载更新”入口，此后才具备新流程。

新安装和检查修复统一使用[最终基准安装器 EXE](https://modelscope.cn/api/v1/models/jiangjiang419/voxcpm-studio-updates/repo?Revision=master&FilePath=installers%2F2.0.3%2F20261019103629-1d02efcb80%2FJVOX-Studio-Installer.exe)（131751424字节）。内置应用与当前签名更新包逐文件一致，新安装即拥有当前全部应用功能与更新体验；模型和依赖按所选功能联网补齐。已安装则自动检查，正常时可直接开始创作；只有发现问题才关闭本目录进程并修复。详见[分发基准包](./分发基准包.md)和[一体版使用说明](./安装修复一体化使用说明.md)。应用包和一体版EXE均经过签名或SHA256校验与匿名完整回读。

## 使用方法

打开根目录 `JVOX Studio配音系统.exe`，点击左侧栏「设置」下方的「检查更新」，会立即手动检查并定位到「设置 → 软件更新」显示结果；检查中禁用重复点击。也可直接进入设置中的软件更新区域操作。自动检查采用支持键盘操作的切换开关，关闭后仍可手动检查。

在本仓库新版流程中，自动或手动检查发现新版均直接打开独立原生窗口。选择「现在更新」后自动下载、校验并进入独立安装，无需再回设置页点击下载或二次确认；选择前请保存工作并结束生成或训练任务。「下次启动更新」关闭提示并继续使用当前版本，不关闭自动检查偏好，下次启动发现新版仍会提醒。关闭提示窗口也视为延期；仍可通过手动检查或「现在更新」重新打开。

原生选择窗口直接使用随应用发布的本地 EXE，不为显示提示下载更新包或初始化 Python。确认后从签名更新包中校验并提取新版原生安装器与事务脚本；两者均准备就绪后工作台才退出。下载或准备失败保留工作台，在独立窗口直接重试。安装不依赖工作台继续运行，新版界面和本地 API 均就绪后才认为成功；安装失败沿用原事务回滚机制。

历史客户端可能仍显示「重启并安装」的确认框，确认框本身是交接前的提示。`20261018135226` 客户端下载签名新脚本后，会转交原生更新器并等待旧主进程退出；更早客户端首次迁移仍可能沿用旧更新脚本。若出现失败循环，请使用单文件修复器。修复完成后可直接使用软件内置更新，无需每次运行修复器。

自动检查只查版本和打开选择窗口，用户选择「现在更新」前不下载或结束生成/训练任务。开关保存在便携包 `data/config/update-settings.json`。

## 已有便携包首次接入

未包含更新模块的历史包需要一次接入，普通用户优先运行上述单文件修复器。当前本机 `builds/VoxCPM-Studio-Electron-Portable-2.0.1` 已接入，应用内部版本为 `2.0.2`；历史目录名不改，以免影响快捷方式。

维护者在源码目录关闭目标程序后执行：

```powershell
python scripts/install_update_support.py "builds/VoxCPM-Studio-Electron-Portable-2.0.1"
```

该脚本使用本机已构建 `dist`，覆盖前把对应旧文件备份到目标 `data/cache/updates/bootstrap-时间/`，失败则恢复。便携包需要已有 Python 3.12 和 `cryptography`，当前基线已验证具备。其他机器也可以用接入后的完整便携目录覆盖应用文件完成首次迁移。

后续新打包会自动包含更新服务、独立窗口、Python 更新器和公钥配置。默认维护根目录 EXE 对应的 `resources/app`，历史 `electron_shell` 开发副本不作为正式入口。

## 保护范围与兼容性

更新白名单仅包含 `resources/app/`、指定的 `app/*.py` 和 `app/src`、`app/conf`、`app/scripts`、`app/assets`。不覆盖 `data`、`models`、`runtime`、`ffmpeg`、`app/studio_config.json`，也不删除清单外的用户文件。

应用更新不覆盖 Electron、音频Python、Torch或模型目录。专用更新Python单独安装在 `data/tools/updater-runtime/运行时ID`，固定哈希配置随签名应用发布；修复器自带初始环境，常规更新可从魔搭下载补齐，并在执行前验证全部文件。音频等核心运行时引入不兼容依赖时，仍需要提高最低基线并另发完整便携包，不得用应用包覆盖它们。

## 维护者构建与发布

在 `Electron版本` 目录执行，发布端需要 `cryptography`、`modelscope` 和本机已登录的 ModelScope 缓存；客户端不使用 ModelScope SDK。

```powershell
# 首次初始化；不会覆盖已有密钥
python scripts/release_update.py --init-key

# 构建、上传、匿名回读校验，最后激活最新入口
python scripts/release_update.py --publish --notes "本次更新说明"

# 只构建、不上传
python scripts/release_update.py --notes "本次更新说明"

# 发布已有构建，不重新构建
python scripts/release_update.py --snapshot "builds/updates/版本-发布序号" --publish
```

正式版本来自前端 `package.json`；每次构建自动生成 UTC 十四位发布序号。同一正式版本可通过更高发布序号更新，避免调试时反复提升正式版本。版本号更低或发布序号更旧的包不会安装。

```text
releases/2.0.2/发布序号/VoxCPM-Studio-2.0.2.zip
public/latest.json
```

发布顺序沿用 SHIYIN：签名构建 → 上传不可变版本包 → 匿名回读大小与 SHA-256 → 激活 `latest.json` → 匿名回读签名入口。客户端固定信任本机公钥，不能采信远端自报的公钥。

私钥位于源码 `.update-private/signing-key`，被 Git 忽略，不进入发布包。应单独保管；丢失后不能直接生成新密钥替换，否则现有客户端无法信任新版本。更新包及客户端均不包含发布凭据。

## 视频依赖冲突导致升级回滚

用户异机日志显示应用文件安装完成后，视频启动探测因 `pyarrow requires NumPy 2.0 or newer, found 1.26.4` 失败。视频固定NumPy 1.26.4，但通过共享音频路径发现了要求NumPy 2的可选Arrow依赖；transformers→sklearn/pandas的间接导入使整个启动验证失败。新版在视频PROBE与实际推理runner中屏蔽不使用的可选Arrow导入，主音频依赖和磁盘文件保持不变，并通过就绪指纹升级让旧环境重新探测。已经在真实视频Python中复现原错误，修复后完整CUDA/NMS、LatentSync和人脸模型探测通过。

## 故障恢复

### 更新后仍反复提示同一版本

正式版本 `2.0.2` 可包含多个发布序号。新版更新面板同时显示当前/最新发布序号，只有更新包逐文件校验、此次新版进程的界面和本地服务健康确认都通过，才记录成功。面板保留上次更新结果，失败回滚会显示原因，并提供「查看更新日志」。下载后再次检查不会丢弃待安装更新；独立更新器完成校验就绪后才退出原程序。

当前正式修复入口为上述单文件EXE（18325504字节）：保存作品并停止生成或训练，双击运行，确认原目录并开始修复，无需解压；即使旧进程隐藏也会自动清理，不要求用户打开任务管理器。不会要求先修好旧Python才能开始。修复成功后在设置中确认发布序号，再检查更新；已保存的模型和作品保留。

修复器在旧客户端之外运行，内置信任公钥，验证签名及全部文件；先尝试正常关闭本目录工作台、旧更新任务及后台子进程，等待两秒后强制结束残留并复检；映像路径和创建时间通过固定句柄核验，排除修复器自身和其他安装。未保存任务可能丢失，界面会提醒先保存。权限不足时显示名称/PID/路径及管理员重试提示。显式修复允许重新安装同一发布的真实文件，已知版本禁止降级。原事务备份完整则恢复；缺失时先验证完整可信包，保留旧事务记录并前向修复。版本记录损坏时使用已识别安装基线和联网可信清单，不伪造当前版本。修复器 SHA256：`834143ff9e55dd1fd1e9f081912d07ace6db9bddde6470ed04236b9d964299fc`。

若修复仍失败，请保留窗口所列的 `updater.log`、`status.json`、`journal.json` 和会话目录，提供完整报错及软件安装路径给维护者。不要卸载、删除原目录或手动删除 `pending.json` / `backup`；环境缺失、权限或安全软件拦截需按日志处理，不能通过修改版本号来掩盖。首次环境未完成时，可用原安装器在原目录继续环境准备，避免改目录创建另一份安装。

已验证两个未修补旧客户端（发布序号 `20261017132910` 和 `20261018131046`）直接在线升级：保留原客户端与旧更新脚本，下载、安装、重启、API健康、再次检查 `current` 均通过，配置和模型保留。本地HTTP迁移验证、修复工具恢复中断损坏主入口与再次安装验证均已通过；公网检查中两份旧发布均为available，新发布为current。

正常旧客户端发布后可走内置更新，无需统一要求用户手动修复。旧客户端的更新器仍可能复制旧版 `updater.py`，因此已经陷入失败循环的机器需保留上述修复入口，不能假设新版脚本会自动修复正在执行的旧更新器。新客户端下载后从签名包提取新版更新脚本，单独校验文件哈希后才执行；这样后续首次迁移即可使用新的启动准备等待机制。

维护者构建/发布单EXE修复器：

```powershell
python scripts/publish_updater_runtime.py

python scripts/publish_legacy_repairer.py <最终签名快照目录> <修复器EXE> --activate
```

构建记录包含独立源码buildId，无需因修复器调试提升正式版本；EXE路径不可变。修复器内置快照可早于激活版本，运行时联网选择更新可信发布。发布记录为快照目录的 `repairer-publication.json`、`publication.json` 和EXE旁的 `发布记录.json`。旧CMD/ZIP工具保留作历史维护用途，优先分发单EXE。

独立 EXE 源码为 `updater/Program.cs`，编译命令 `python scripts/build_standalone_updater.py`，使用与安装器相同的 Windows .NET Framework 编译器。签名包构建、轻量包、完整便携打包和 Electron Builder 均包含该 EXE。编译产物被 Git 忽略；每次构建核对源码与产物哈希。下载时原生 EXE 和 Python 事务脚本都须通过签名清单中的文件哈希校验，原生窗口的 host-ready 与事务的 ready 回执须与本次会话及进程对应，主程序才允许退出。

安装器和更新器的共享样式在 `bootstrap/SharedTheme.cs`，分别编译到各自 EXE，运行时不读取彼此文件。新增客户端传递工作台当前主题，独立窗口也支持手动切换；历史客户端未传主题时默认安装器同款浅色。`python scripts/render_standalone_updater.py` 使用实际窗体渲染各状态、主题和尺寸，并验证切换不重置状态及关闭保护；不会运行更新事务。

- 下载断开时保留 `.part`，再次点击下载会请求 Range；服务端忽略 Range 时从头下载，不拼接错误内容。
- 魔搭 CDN 要求请求带 `User-Agent`；客户端使用 `VoxCPM-Studio-Updater/1.0`。
- 独立更新会话位于 `data/cache/updates/session-UUID/`，包含 `updater.log`、签名清单、`journal.json`、文件备份和 `status.json`。
- 更新器等待旧主进程退出后安装，逐文件记录备份与事务。重启后等待 React 渲染确认和本地 API 健康确认；失败回滚。
- 更新途中掉电后，正常启动会检测未完成事务；更新进程已退出时使用专用环境恢复旧文件，再重新启动以加载完整旧代码。若界面主入口损坏不能启动，优先运行单文件修复器。维护者也可关闭所有该目录程序后直接恢复：

```powershell
.\data\tools\updater-runtime\py312-crypto47-30fd13431522\python.exe -B .\resources\app\updater.py "完整会话目录" --recover
```

更新记录用于恢复，不主动清理用户数据。确认升级稳定后可以自行归档较旧的更新会话，勿清理正在安装的会话或唯一私钥。
