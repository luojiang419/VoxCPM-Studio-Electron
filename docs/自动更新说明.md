## 使用方法

打开根目录 `VoxCPM Studio.exe`，点击左侧栏「设置」下方的「检查更新」，会立即手动检查并定位到「设置 → 软件更新」显示结果；检查中禁用重复点击。也可直接进入设置中的软件更新区域操作。默认在音频系统和所选功能真实启动完成、工作区可用后自动检查一次，有新版时弹窗提醒；关闭自动检查后仍可使用手动按钮。发现新版后下载，保存工作并点击「启动独立更新器」，确认任务已结束。原生更新窗口和事务进程均准备好后工作台才退出；安装过程不依赖工作台继续运行，新版界面和本地 API 均就绪后才认为成功。失败会回滚应用文件并重新打开旧版。

历史客户端可能仍显示「重启并安装」的确认框，确认框本身是交接前的提示。`20261018135226` 客户端下载本次签名新脚本后，会转交原生更新器并等待旧主进程退出；更早客户端首次迁移仍可能沿用旧更新脚本。若出现失败循环，请直接使用新版独立修复包，避免反复重试旧更新器。

自动检查只查版本，不会自动下载或强制结束生成/训练任务。开关保存在便携包 `data/config/update-settings.json`。

## 已有便携包首次接入

未包含更新模块的历史包不能凭空获得更新功能，需要一次接入。当前本机 `builds/VoxCPM-Studio-Electron-Portable-2.0.1` 已接入，应用内部版本为 `2.0.2`；历史目录名不改，以免影响快捷方式。

维护者在源码目录关闭目标程序后执行：

```powershell
python scripts/install_update_support.py "builds/VoxCPM-Studio-Electron-Portable-2.0.1"
```

该脚本使用本机已构建 `dist`，覆盖前把对应旧文件备份到目标 `data/cache/updates/bootstrap-时间/`，失败则恢复。便携包需要已有 Python 3.12 和 `cryptography`，当前基线已验证具备。其他机器也可以用接入后的完整便携目录覆盖应用文件完成首次迁移。

后续新打包会自动包含更新服务、独立窗口、Python 更新器和公钥配置。默认维护根目录 EXE 对应的 `resources/app`，历史 `electron_shell` 开发副本不作为正式入口。

## 保护范围与兼容性

更新白名单仅包含 `resources/app/`、指定的 `app/*.py` 和 `app/src`、`app/conf`、`app/scripts`、`app/assets`。不覆盖 `data`、`models`、`runtime`、`ffmpeg`、`app/studio_config.json`，也不删除清单外的用户文件。

这是应用代码更新，不包含 Electron、Python、Torch 或其他第三方运行时的升级。引入新运行时依赖或改变其 ABI 时，需要提高最低基线并另外提供完整便携包；不得用应用包覆盖这些目录。

## 维护者构建与发布

在 `Electron版本` 目录执行，发布端需要 `cryptography`、`modelscope` 和本机已登录的 ModelScope 缓存；客户端不使用 ModelScope SDK。

```powershell
# 首次初始化；不会覆盖已有密钥
python scripts/release_update.py --init-key

# 构建、上传、匿名回读校验，最后激活最新入口
python scripts/release_update.py --publish --notes "本次更新说明"

# 只构建、不上传
python scripts/release_update.py --notes "本次更新说明"

# 发布已有构建，不重新构建
python scripts/release_update.py --snapshot "builds/updates/版本-发布序号" --publish
```

正式版本来自前端 `package.json`；每次构建自动生成 UTC 十四位发布序号。同一正式版本可通过更高发布序号更新，避免调试时反复提升正式版本。版本号更低或发布序号更旧的包不会安装。

```text
releases/2.0.2/发布序号/VoxCPM-Studio-2.0.2.zip
public/latest.json
```

发布顺序沿用 SHIYIN：签名构建 → 上传不可变版本包 → 匿名回读大小与 SHA-256 → 激活 `latest.json` → 匿名回读签名入口。客户端固定信任本机公钥，不能采信远端自报的公钥。

私钥位于源码 `.update-private/signing-key`，被 Git 忽略，不进入发布包。应单独保管；丢失后不能直接生成新密钥替换，否则现有客户端无法信任新版本。更新包及客户端均不包含发布凭据。

正常旧客户端发布后可走内置更新，无需统一要求用户手动修复。旧客户端的更新器仍可能复制旧版 `updater.py`，因此已经陷入失败循环的机器需保留上述修复入口，不能假设新版脚本会自动修复正在执行的旧更新器。新客户端下载后从签名包提取新版更新脚本，单独校验文件哈希后才执行；这样后续首次迁移即可使用新的启动准备等待机制。

维护者构建公开修复包使用 `python scripts/build_update_repair.py <已签名快照目录> --output <新目录>`，发布并在匿名回读后激活同一快照使用 `python scripts/publish_update_repair.py <已签名快照目录> <修复ZIP> --activate`。不覆盖既有不可变产物；发布记录保存在快照目录的 `repair-publication.json` 和 `publication.json`。

独立 EXE 源码为 `updater/Program.cs`，编译命令 `python scripts/build_standalone_updater.py`，使用与安装器相同的 Windows .NET Framework 编译器。签名包构建、轻量包、完整便携打包和 Electron Builder 均包含该 EXE。编译产物被 Git 忽略；每次构建核对源码与产物哈希。下载时原生 EXE 和 Python 事务脚本都须通过签名清单中的文件哈希校验，原生窗口的 host-ready 与事务的 ready 回执须与本次会话及进程对应，主程序才允许退出。

- 下载断开时保留 `.part`，再次点击下载会请求 Range；服务端忽略 Range 时从头下载，不拼接错误内容。
- 魔搭 CDN 要求请求带 `User-Agent`；客户端使用 `VoxCPM-Studio-Updater/1.0`。
- 独立更新会话位于 `data/cache/updates/session-UUID/`，包含 `updater.log`、签名清单、`journal.json`、文件备份和 `status.json`。
- 更新器等待旧主进程退出后安装，逐文件记录备份与事务。重启后等待 React 渲染确认和本地 API 健康确认；失败回滚。
- 更新途中掉电后，正常启动会检测未完成事务；更新进程已退出时先恢复旧文件。若界面主入口损坏不能启动，可关闭所有该目录程序，再使用包内 Python 直接恢复：

```powershell
.\runtime\python\python.exe .\resources\app\updater.py "完整会话目录" --recover
```

更新记录用于恢复，不主动清理用户数据。确认升级稳定后可以自行归档较旧的更新会话，勿清理正在安装的会话或唯一私钥。
