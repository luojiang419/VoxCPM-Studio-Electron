# EE2X统一授权中心与JVOX试用版本设计

2026-10-25。用户选定视觉方案2：石墨深灰、银白主按钮、横向导航；用户列表在左、授权操作在右。已实现真实认证服务、管理员页面、Electron注册登录与退出、Python/API门禁，并部署至用户指定的 `/opt/useradmin`；独立试用便携包已构建。实际运行与交付见 `统一授权生产验收.md`，历史 `authorization-demo/` 仍仅用于演示。

## 目标与产品流程

采用统一身份、按软件独立授权。账号可跨多款软件登录，但某款软件的试用与永久权限只对对应app_id生效。

用户从软件注册时自动领取该软件一个自然月试用；已有账号首次进入其他软件时单独领取该软件试用，不消耗尚未使用的软件期限。10月25日注册，11月25日同一时刻到期；1月31日注册，非闰年2月28日同一时刻到期。时间存储UTC、显示Asia/Shanghai，服务器签发时间为权威。

管理员可随时按用户和软件修改试用到期时间，不受默认一个月限制：指定北京时间日期和时刻，延长、缩短、立即结束，或将已过期账户延至未来恢复试用。永久授权保持独立，不因调整试用被误降级。变更必须填写原因，并保存管理员、原到期时间、新到期时间与修订号；重复保存相同时间不重复记审计。倒计时和最后7天提醒按新期限重算，但同一自然日不重复弹窗。

生产管理端修改成功即更新服务器权威记录、增加entitlement revision；在线客户端下一次静默刷新（最长5分钟，或用户主动刷新）后应用最新期限。离线设备无法实时接收缩短后的期限，最迟在既有试用租约失效时要求联网，当前最长72小时。若要求缩短期限立即对所有设备生效，需改成强制在线验证，不能同时承诺72小时离线可用。

平时只在侧栏/账户页显示剩余时间，不弹窗。0＜剩余时间≤7×24小时时，每个用户、每款软件、每个北京时间自然日最多自动提醒一次。提醒包含作者联系方式、用户编号、软件名及购买说明。过期后停止新生成、训练、声音克隆、音乐、视频、批量和开发者API任务，保留登录、授权刷新、更新、已有作品的查看/播放/导出，不打断已经运行的任务。队列尚未开始的任务在真正执行前重新校验授权。

作者在外部收款后，后台检索用户，核对用户编号与软件、勾选收款确认、填写备注，二次确认永久开通。此操作需要数据库事务、请求幂等键、操作审计。客户端启动时刷新，运行中每5分钟静默刷新；用户可主动刷新，建议成功开通后最长5分钟自动生效，不承诺没有连接机制的“立即推送”。

## 页面与入口

- `https://admin.ee2x.cn/admin/login`：管理员登录，使用用户指定凭据在服务器首次启动时初始化；首次完成后不重复覆盖数据库，后台可修改用户名和密码。本文与源码不包含该初始密码。
- 管理页“用户授权”：按软件检索用户，查看试用、到期、永久权限和设备数量，开通、改期、停用和恢复，变更记录审计。
- 管理页“软件接入”：新增软件、固定app_id、配置设备限制、作者联系方式和购买说明。当前统一默认一个自然月试用，单个用户期限可独立调整；二维码上传与最低版本策略留作后续扩展。
- 管理页“操作记录”：查看授权变更、操作者和前后期限，不记录密码、完整Token或签名私钥。
- 管理页“账户设置”：修改管理员用户名和密码。上述页面在同一管理应用中切换，真实入口为 `/admin/login`。
- 软件左下角“登录 / 注册”“账户与授权”：真实用户注册、登录、倒计时、刷新与退出。当前没有独立的Web普通用户门户。
- `/api/v1`：统一版本化认证协议，未来新软件复用客户端SDK。

历史演示工程以单页内部视图模拟交互，浏览器内数据不参与实际授权。生产系统改为服务器数据库、真实会话和签名授权，桌面凭据由Windows保护存储。

## 服务部署

参考根项目 `DOC/公网部署.md` 的方式A，在服务器直接运行独立授权服务；不使用个人电脑FRP作为生产认证依赖，不修改已有lwai站点服务。

实际管理前端为独立原生JavaScript静态应用，后端FastAPI单实例＋SQLite WAL；桌面保持React/TypeScript。前后端同域，OpenResty代理至本机4102端口。部署目录按用户最新要求为 `/opt/useradmin`，独立systemd服务 `ee2x-auth`，专用用户运行。未来可按容量需求迁移PostgreSQL。

上线已按腾讯云服务器文档完成SSH、DNS、有效TLS证书、数据库与管理员初始化、HTTPS回源、未登录401/403、数据库恢复验证及真实桌面联调。证书模拟续期通过。旧公网部署手册中的另一台服务器不作为本服务运行位置。

数据库以一致性备份方式处理WAL，备份加密且与签名密钥分开保存；发布先做迁移备份，保留回滚版本，回滚代码时需检查数据库兼容性。健康检查不暴露用户数据。

## 数据模型与隔离

| 表 | 核心字段与约束 |
| --- | --- |
| users | id、username_norm唯一、email_norm可选唯一、password_hash、status、created_at |
| admins | id、username_norm唯一、password_hash、credential_version、status；独立管理身份 |
| applications | id/app_id唯一、name、enabled、trial_months、device_limit、offline_hours、contact配置 |
| entitlements | user_id、app_id联合唯一；kind、trial_started_at、trial_expires_at、granted_at、status、revision |
| devices | user_id、app_id、device_id、device_key、last_seen_at、revoked_at；设备限额在事务中检查 |
| sessions | identity_type、identity_id、refresh_hash、expires_at、revoked_at、设备关联 |
| license_keys | id、app_id、digest唯一、prefix、entitlement_id、status；可选人工兑换入口 |
| audit_logs | actor、action、target_user、app_id、request_id唯一、before/after、note、time |
| reminder_receipts | user_id、app_id、Asia/Shanghai日期联合唯一；设备端同时记录提示标记 |
| trial_device_history | app_id、带服务端盐的设备摘要、首次领取记录，限制重复注册领取 |

每次读写授权均从已认证身份推导user_id，不能信任客户端传入的其他用户ID。管理接口进行独立管理员授权，跨软件授权查询必须显式限定app_id。注册、试用创建、设备激活和收款开通使用事务及唯一约束处理并发，而非先查再写的竞态实现。

## 自动密钥与签名授权

注册后服务器生成授权记录和可追踪授权编号，再签发绑定用户、软件、设备与期限的租约。用户无需复制粘贴密钥即可使用。可扩展人工兑换码功能，随机原始兑换码只展示一次，服务端仅存安全摘要，禁止全体用户共用一个内置密钥。

客户端保存验签公钥，签名私钥仅在服务器。签名载荷至少包含schema_version、kid、issuer、aud/app_id、user_id、device_id、entitlement_id、kind、issued_at、lease_expires_at、trial_expires_at、revision。验证签名和固定算法，同时检查签发者、软件、设备、期限、版本和撤销状态。不能只解码JWT就当作通过认证。密钥轮换允许旧公钥在迁移期验签，不能把应用更新签名私钥复用为授权签名私钥。

密码Argon2id哈希，初始化凭据从私密环境读入，不写Git或前端；登录统一错误、限速与失败退避。Web管理端使用HttpOnly/Secure/SameSite Cookie并保护CSRF，修改凭据后撤销既有会话；桌面refresh token由Electron主进程存入Windows凭据保护存储，不暴露给渲染进程，refresh token轮换并检测复用。

首次注册与激活必须联网。建议试用离线租约最长72小时且不跨过trial_expires_at。联网失败优先使用仍有效的签名租约；超过租约时提示联网验证并暂停新任务，不能把网络错误当永久封禁。检测明显时钟回拨后要求联网校时，不仅依赖可修改的本地配置。

永久授权默认允许长期离线，需明确它与即时撤销不能同时保证：离线设备只能在再次联网后获知封禁/撤销。若后续要求最长72小时内撤销，需改为短租约并要求永久用户定期联网，属于需确认的产品政策变化。本地Electron与Python代码不能保证绝对防破解；现有无授权历史版本也不能被新认证服务追溯控制。

## 实际接口

| 接口 | 行为 |
| --- | --- |
| POST /auth/register | 注册并为指定app_id原子创建试用，返回账号及登录会话 |
| POST /auth/login | 登录，返回短会话；首次接入其他软件单独领取试用 |
| POST /auth/refresh、/auth/logout | 轮换/撤销会话 |
| GET /me | 返回本人资料与会话CSRF信息，不接受任意user_id读取 |
| POST /auth/register、/auth/login | 同时为指定软件幂等领取/绑定设备，检查重复领取策略 |
| POST /licenses/refresh | 签发最新签名授权与权威server_time |
| GET /me/devices | 返回本人设备记录 |
| POST /devices/release | 在策略范围内解除本人设备；保留试用历史，不能借解绑刷新期限 |
| GET /apps/{app_id}/public-config | 软件名、联系渠道与购买说明，不含管理密钥 |
| POST /admin/auth/login | 管理员独立登录 |
| GET /admin/state | 返回管理数据，当前用户最多1000条、授权2000条、审计200条；管理界面按软件及搜索筛选 |
| POST /admin/entitlements/{id}/grant-permanent | 检查管理员、收款确认、幂等键和目标软件；事务更新并记审计 |
| POST /admin/entitlements/{id}/suspend、/restore | 明确的管理授权变更与原因 |
| POST /admin/entitlements/{id}/trial-expiry | 指定expires_at与reason，可延长/缩短/结束/恢复试用；事务审计before/after，增加revision，幂等键和预期revision防止并发覆盖 |
| POST /admin/apps、PUT /admin/apps/{id} | 新增/配置软件、设备数及联系信息 |
| PATCH /admin/account | 修改管理员账号凭据并撤销旧会话 |
| GET /health、/public-key | 存活检查和公开签名公钥信息；客户端仍固定信任已配置公钥，不自动替换 |

后续软件接入包分为TypeScript/Electron客户端、Python服务端验证器与协议文档。app_id不是秘密，桌面端不内置通用client_secret。桌面内API服务的既有开发者调用密钥与购买授权分工不同，保留原有按API Key隔离设计，在任务执行处叠加使用权检查。

## 桌面修改点与试用打包

- `frontend/voxcpm_studio_electron/main.js`：认证客户端、凭据保护、登录/授权IPC、网络刷新与服务器时间处理。
- `preload.js`：最小授权API桥接，禁止任意URL请求或泄漏refresh token。
- 新 `license-service.js`：签名验证、租约/设备绑定、缓存、离线和状态机，保持公共协议与具体业务解耦。
- React账户页/注册登录、侧栏倒计时与最后一周弹窗；提醒分软件和北京时间日期去重。
- `backend/voxcpm/studio_api.py`、`studio_public_api.py`与任务队列：受保护新任务入口和执行前统一验证；未授权时返回结构化错误，已有作品读取保持可用。
- 构建/更新：独立trial通道、签名元数据与安装包身份；每次更新必须保留认证模块，禁止从旧正式入口恢复到无授权版本。开发者安装与现有用户迁移政策单独明确。

当前交付独立试用便携ZIP，含桌面、业务代码与独立验签依赖，解压后直接运行试用EXE；不复制33GB模型。首次用户仍按既有清单补齐缺失Python/CUDA/模型；本机验收只读复用已安装资源。分发不包含管理员凭据、作品、账号缓存、已激活证书或签名私钥。试用版当前停用正式版自动更新入口，后续采用独立签名试用分发。

## 生产完成条件

1. 注册并发只创建一份授权；重复登录、重装、改本地配置不能重置服务端试用。
2. 自然月、月末、闰年、时区、7天边界、到期瞬间与提醒去重均有测试。
3. 开通/延期/停用按用户与软件准确执行，越权401/403、跨软件隔离和重复开通幂等通过。
4. 设备激活并发不突破上限；解绑不删除试用历史；离线租约、回拨与网络恢复表现符合方案。
5. Electron渲染进程、Python直接接口、开发者语音API、批量/排队任务均经过授权检查。
6. 真实HTTPS注册→桌面试用→后台收款确认→客户端永久授权闭环；服务器重启、会话过期与数据库恢复验收。
7. 在隔离目录安装试用包并验证启动、倒计时、升级、修复和用户数据保留；不在正式安装上做破坏验证，不重新下载已有模型。
8. 生产管理员密码可修改且旧会话失效；源码/打包产物扫描不含私钥、凭据和个人数据；提供运行文档、恢复点及Git提交。
