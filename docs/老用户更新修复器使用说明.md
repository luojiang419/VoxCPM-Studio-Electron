# 老用户更新修复器

适用于已经安装 JVOX Studio配音系统，但升级后仍是旧界面、反复提示同一更新，或旧更新组件损坏的 Windows 64 位用户。

[下载单文件修复器 EXE（约17.5 MiB）](https://modelscope.cn/api/v1/models/jiangjiang419/voxcpm-studio-updates/repo?Revision=master&FilePath=repairers%2F2.0.2%2F20261018235215-0f71f753d9%2FVoxCPM-Update-Repairer.exe)

可直接把这个 EXE 或下载链接发给老用户，不需要附带其他文件，也不需要安装 Python、Node 或开发工具。

## 用户操作

1. 保存作品并停止生成或训练任务。
2. 双击修复器，确认显示的是原来的软件安装目录。找不到时点击「选择目录」，选择包含 `JVOX Studio配音系统.exe` 的原目录。
3. 联网，点击「开始修复并升级」；修复器会自动关闭该目录的工作台、旧更新器和后台进程，残留时强制结束。等待显示「修复完成，更新通道已验证」并自动打开软件。
4. 以后直接在软件内「检查更新」并启动独立更新器，无需每次运行修复器。

不要新建一份安装目录、卸载原软件或删除原目录。默认目录会自动检测，自定义位置可手动选择；如果原安装在另一台电脑，请把修复器发到那台电脑运行。

修复在原目录进行，保留已保存的模型、配置、音色、作品和已有功能选择。无需重新下载已有模型。工具会替换损坏的应用和更新组件、修正属于该目录的旧启动入口，并安装独立的更新运行环境；不会依赖旧音频 Python 执行修复。

## 修复后如何确认

当前公开应用为 `2.0.2 / 20261018235215`。同一正式版本可能有不同发布序号，不能只看 `2.0.2` 判断是否更新。修复器联网获取最新可信发布，以届时公开版本为准；内置签名快照序号为 `20261018235215`。

修复成功需要通过应用文件核验、实际启动健康检查和已安装更新服务的通道检查。也可在设置中核对当前/最新发布序号，再检查更新；当前已是最新时应显示无需更新。

如果新版同一发布中的更新文件损坏，可以再次运行修复器进行真实文件修复；不会仅修改版本标记。修复器拒绝降级。点击开始后会先尝试正常关闭，等待两秒后强制结束残留进程；未保存内容和正在进行的任务可能丢失，请务必先保存。

## 自动关闭隐藏进程

修复器按原安装路径、精确脚本参数及后台父子关系识别进程，不按名称批量结束。操作前核对Windows进程句柄的映像与创建时间，避免误操作复用的PID；保留其他安装目录、其他Python程序和修复器自身。日志与 `stopped-processes.json` 记录本次已关闭/强制结束进程的名称、PID、路径及方式。

若没有结束进程的权限，窗口会列出阻塞进程；右键修复器，选择「以管理员身份运行」后再试。

本版也修复日志中视频对口型环境的 `pyarrow requires NumPy 2.0 or newer, found 1.26.4`：只在视频子进程中隔离不需要的可选Arrow依赖，不升级主音频NumPy、不删除用户依赖，旧视频就绪记录会重新验证。

## 失败时保留什么

点击「查看更新日志」，保留日志和完整错误内容，并把原安装路径一并提供给维护者。不要手动删除 `pending.json`、`journal.json` 或 `backup`。

- 修复器日志：`%LOCALAPPDATA%\VoxCPMStudioRepair\sessions\日期时间-会话ID\updater.log`。
- 原目录中的事务和备份：`data\cache\updates\session-repairer-*`。
- 原目录中的后续更新环境：`data\tools\updater-runtime\运行时ID`；正常更新会校验，缺失或损坏时自动补齐。

上次更新中断且备份完整时先恢复；备份丢失时，工具会先验证完整签名更新包，保留旧记录，再执行前向修复。网络、写入权限、安全软件拦截或原音频环境损坏仍需依据日志处理；更新通道独立不代表所有音频运行故障都会被修复。
