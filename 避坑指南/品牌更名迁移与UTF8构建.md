# 品牌更名迁移与 UTF-8 构建

适用：2026-10-19，JVOX Studio配音系统 2.0.3 正式更名。

## 中文包元数据导致 Windows 打包失败

表现：package.json 加入中文 description/productName 后，轻量包在读取版本号时抛出 `UnicodeDecodeError: gbk`。

根因：`Path.read_text()` 使用 Windows 默认编码；原 JSON 全为 ASCII 时掩盖了隐患。

解决：构建脚本读取 JSON 显式传入 `encoding="utf-8"`（或位置参数 `"utf8"`），不依赖当前机器语言及环境变量。

验证：签名快照和轻量桌面包逐文件一致，安装修复一体版编译及真实安装/修复通过。

## 卸载时不能通过文件是否存在判断快捷方式原目标

表现：主程序改名后，安装集成测试发现卸载遗留自身快捷方式。

根因：卸载先删除主程序，后清理快捷方式。入口解析器检查新版 EXE 已不存在后回退旧名称，导致新名称快捷方式匹配失败。

解决：归属判断同时比较新旧两个固定、位于同一安装根目录的主程序路径；只删除目标确属当前安装的记录。运行中的进程保护也同时覆盖新旧进程名。

验证：26 项原生安装集成通过，包含真实快捷方式/注册表、同名其他软件保护、卸载保留数据与占用文件恢复。

## 更名不改变升级信任链和用户身份

更新源仓库ID、签名公钥、manifest product、appId、内部包标识、环境变量、安装归属标记及用户数据位置保留兼容。新安装采用新主程序名称，升级旧版时创建新入口，保留旧 EXE 为旧快捷方式兼容入口。

根目录新入口的创建独立记入事务日志，失败时只移除哈希与本次复制匹配的文件；已存在的入口不覆盖。旧安装的新卸载器/图标来自已验签应用快照，替换前备份；失败时恢复。快捷方式迁移只处理归属记录中且实际目标位于当前根目录的文件；其他软件同名入口不覆盖。

验证：5 项专门迁移回归、真实 Windows COM/隔离注册表、2.0.2 未修改客户端直升、独立更新后 API 健康与数据保持通过。所有测试使用隔离目录。

## 首次启动庆祝页不能依赖后端就绪

等待 bootstrap ready 才打开公告，会使用户先看到工作台或资源准备页。只移除 ready 条件也不够：后打开的资源准备模态可能抢占顶层，主窗口立即show还会闪出空背景。

首次庆祝页独立于工作台容器，进入前隐藏工作台；资源准备组件持续接收状态，但在庆祝期间不调用showModal，进入后恢复当前准备/错误。使用布局effect在首次绘制前打开庆祝模态和设置主题，主窗口等ready-to-show才展示；安装准备模式仍保持隐藏。rendererReady及后台准备不等待用户确认，保证安装/更新握手可完成。

验证：隔离真实主程序、延迟后端后记录ready-to-show首帧，庆祝模态已打开且工作台隐藏；注入待处理资源错误不会覆盖，继续后错误可见并衔接真实API启动；确认后真实退出/重启不重复。最终安装器的准备窗口隐藏和renderer/API握手仍通过。
