# 项目测试资源与空间清理

表现：项目文件逻辑总量约 222.10 GiB，G 盘剩余约 48.6 GiB；安装、修复与界面验收后持续增长，普通验证可能触发 GB 级模型或 GPU 依赖下载。

根因：多代桌面完整副本与安装器、隔离测试环境、模型链接/副本、音乐运行包的合并 ZIP/分片/展开目录同时保留；还存在 2.33 GiB 的 `.wget.partial` 和 pip 升级残留 `~orch` 等目录。只按文件大小求和会重复计算硬链接；Windows 的 `os.scandir().stat()` 中 inode/link 数可能为零，核对硬链接时必须对具体路径使用 `os.stat()`。

解决：模型和音乐环境统一到项目根位置，旧路径使用 junction；保留最新分发和签名快照、当前测试依赖以及固定离线安装资源。下载器先校验目标与显式本地源，匹配后复制；常规验收用 `validate_local.ps1` 的离线模式。清理执行采用原生 PowerShell，验证所有绝对目标及上级路径，删除目录前只移除内部链接，不穿透目标；默认预览，显式 `-Apply` 执行。

跨项目占用：旧音乐暂存环境与 `G:/app/minimax/.venv` 存在同 inode 的硬链接，MiniMax/ComfyUI 运行时会导致 Windows 拒绝删除映射中的 PYD/DLL。不能把这种失败当成 ACL 损坏，不能强制结束其他项目；继续删除未占用文件，保留映射链接。剩余 249 个文件约 4.15 GiB 逻辑大小，但各文件均有其他硬链接，独占物理数据为 0；关闭占用项目后可再次清理这些链接。

验证：33 项 Node 运行环境测试与 11 项视频资源测试通过，覆盖本地源复用、同大小损坏拦截、离线拒绝下载、完整断点复用、复制后独立修改以及既有续传/取消逻辑。另实际验证 junction 目标哨兵未被删除、越界清单被拒绝；清理后最新安装器与签名 ZIP 的 SHA256 仍与正式基准一致。明细见 `builds/storage-cleanup/`，凭据配置保留副本不提交 Git。
