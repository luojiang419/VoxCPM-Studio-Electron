# 模型完整但使用前校验误报

表现：安装器已下载并校验模型，音乐页显示就绪，生成时仍提示“模型资源缺失或损坏”。日志内部原因是“文件校验失败或校验期间被修改”，无法区分内容与元数据变化。

根因：`studio_resources.verify_files` 哈希计算前后直接比较完整 `stat_result`。该对象包含访问时间，正常读取也会改变 `st_atime`，因此文件内容和大小完全正确仍会被拒绝。另一个独立问题是自定义音乐模型目录未传给使用前校验，导致界面、推理与校验目录不一致。

实证：2026-10-19 在本机 `D:\Program Files\VoxCPMStudio` 读取 ACE 权重，大小 9,974,719,892 字节，SHA256 `86a1afb0a1f711f0e3304ff65d874df3ae6783db683dcf982513fb9b6d14ae71` 与安装清单一致；全部 4 个 ACE 资源通过新校验。前后完整 stat 比较仍为不同，唯一变化为 `st_atime_ns`。记录：`builds/model-auto-repair-validation/1792395225580400900/report.json`。

解决：只比较内容相关的大小、修改时间、变化时间及设备/文件身份，忽略访问时间；保留 SHA256 和已验证文件缓存。音乐校验显式使用实际模型目录及当前资源清单。错误说明区分找不到文件、大小不符、SHA256 不符和校验期间变化，并提供实际路径。

自动修复：仅对已启用、音乐运行环境已就绪的当前模型补齐缺失或异常文件。正确文件复用缓存；先下载到 `.part`，支持取消、断点续传，校验通过后原子替换，失败不覆盖旧文件。共享模型若为硬链接，只替换托管目录条目，不写坏共享源。用户已移除模型不自动重装。

验证：访问时间变化回归、真实本地 HTTP 下载/续传/取消/错误、权限与空间不足保护、API 原任务内修复后继续、真实 Electron 交互通过。D 盘安装已备份并应用修复，实际程序/API 启动及 ACE 就绪检查通过，模型下载 0 次；未执行真实音乐权重推理。遇到相似问题应先核对实际路径与 SHA256，不直接要求重下大模型。
