# 音乐运行包隔离与源码过滤

表现：原环境可运行，独立嵌入式 Python 中导入 ComfyUI 却报 `comfy.ldm.models`、`comfy_api.input` 缺失；HeartMuLa 导入报 `omegaconf` 缺失。

根因：递归排除所有名为 `models`、`input` 的目录，会误删 ComfyUI 内部源码。只从 ComfyUI requirements 收集依赖，也不会覆盖 HeartMuLa 依赖覆盖层的完整依赖闭包。

解决：仅在 ComfyUI 根目录排除权重、输入输出、自定义节点与用户数据。运行库按实测 distribution 元数据收集依赖闭包，包含 HeartMuLa 覆盖层的根依赖；基础音乐环境与 HeartMuLa 旧版本依赖分开，并与 VoxCPM 的语音/对口型 Torch 环境隔离。

验证：必须在实际 ZIP 解压后的嵌入式 Python 中分别启动独立进程，强制离线导入 ACE、MiniMax Music 3、YuE2、HeartMuLa，并执行 CUDA 小矩阵。此检查不等于重新完成整曲生成；Windows eager 路径的可选 Triton 警告不能误判为必须在线安装的依赖。

对应实现：`scripts/build_music_assets.py`、`backend/voxcpm/music_install.py`、`backend/voxcpm/music_worker.py`。本机完整运行包安装及四模型自检已在任务015完成。
