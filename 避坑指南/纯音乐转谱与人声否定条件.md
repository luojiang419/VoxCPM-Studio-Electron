# 纯音乐转谱与人声否定条件

表现：YuE2 纯音乐按钮曾被显式禁用；简单取消禁用并传空歌词，不能保证把原规划的人声旋律作为器乐条件。纯音乐提示词校验还可能把 MiniMax 的 `Vocal Details` 标题及“禁止说唱与口白”误判为正向人声。

根因：YuE2 规划包含 Vocal 与 Ins 声部，音符事件和原谱 token 都参与后续条件；字符串改轨名或复用旧 token 不会完成可靠转谱。人声否定列表中的中文“与”、英文 Oxford comma，以及行内标题，需要先识别再检查正向要求。

解决：使用安装包原生 `notation.read/write` 转移音符，保留音高、起音、时值、和弦、速度和小节网格；重叠处主旋律优先，保留原 Ins 未重叠片段并记录裁剪。通过 `YuE2Plan` 规划后，交给真实 `YuE2RenderPlan` 时清空原谱和旧 ids，显式传入固定新谱，复核实际 score。先去除中英文人声标题与无人声否定列表，再检测演唱、哼唱、吟唱、说唱、口白；颂钵 `singing bowls` 属于乐器。

验证：`python scripts/test_music_suite.py -p no:cacheprovider`；`pwsh -File scripts/validate_local.ps1 -Script scripts/smoke_music_instrumental_score.py` 验证真实曲谱接口和 Render Plan 的新谱重新编码分支，GPU 数值阶段使用夹具；实际四模型 AI 提示词验证已通过。2026-10-20 本机 GPU 验收因正式安装缺少 YuE2 权重停止，未下载或改写安装资源，不能把契约验证报告为实际音频生成成功。
